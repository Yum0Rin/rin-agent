# 企业微信 / IM 接入

> 本目录只给**接口设计**，不包含任何私有实现、数据库解密、会话存档抓取或真实凭证。
> 原始 Rin 是一个私人企业微信项目；本仓库刻意不带上那部分代码。

## 1. 整体结构

```text
企业微信 / 其他 IM
        │  收消息（WebSocket / 回调 / 轮询）
        ▼
你的网关进程
        ├─ 识别发送者：userid → owner / partner / guest
        ├─ 组装 prompt：人设 + 状态 + 最近笔记 + 提醒
        ├─ 调 LLM（OpenAI 兼容）
        ├─ 执行工具：记笔记 / 查笔记 / 建提醒 / 写待办 / 排日程
        └─ 回复（被动回复 / 主动推送）
```

平台层只做「消息转换 + 发送」；自然语言不写正则路由，交给模型判断并调用工具。显式 `/命令` 可以保留确定性分支。

## 2. 企业微信智能机器人

- 用官方「智能机器人」能力：Bot ID + Secret，WebSocket 长连接或回调。
- 单聊按 `userid` 识别；群聊按 `chatid` + 发送者 `userid` 识别。
- 群聊里机器人通常只能收到 **@ 它** 的消息；不要为了补上下文去抓本地数据库（见第 6 节）。
- 被动回复有超时限制；长任务先回一句「在弄」，再异步发结果。
- 主动推送能力有限；定时提醒优先写进企业微信待办 / 日程，让平台自己提醒。

## 3. 身份映射

```json
{
  "users": {
    "owner": { "name": "小满", "title": "姐姐", "mode": "sunny" },
    "partner": { "enabled": true, "name": "阿澈", "title": "阿澈", "mode": "sharp" }
  }
}
```

网关里维护：

```python
USER_BY_ID = {
    "zhangsan": "owner",
    "lisi": "partner",
}
```

未知 userid → 用 `owner` 的晴天模式，但少用称呼；不要默认把陌生人当 partner。

## 4. 群聊规则

- 群聊是公共场合：只接公共话题和 `shared` 内容。
- 不展开私聊历史、个人档案、情绪细节。
- 两个人都在场时点名说话，不只叫「你 / 他」。
- 群里禁用私密查询：`note_search` / `note_recent` 只返回 `shared`；`reminder_list` 只返回当前发送者的。
- `@Rin` 是「结算」信号：只挑真正需要接的回复，不是每条都插嘴。

## 5. 工具映射

| Rin 工具 | 企业微信侧 |
|---|---|
| `note_add` | 写本地 SQLite；需要共享时同步到智能文档 |
| `note_search` | 本地 SQLite 检索 |
| `reminder_add` | 企业微信待办 / 日程 API |
| `todo_create` | 官方待办 API |
| `schedule_create` | 官方日程 API，支持周期规则 |

执行结果要回传一条短回执，人设只复述这一句。不要在模型回复里复述整张日程表。

## 6. 不要做什么

- **不要抓企业微信本地数据库**：解密本地库、镜像群消息可能违反服务条款，且客户端版本升级会失效。原始私人项目做过这件事，本仓库不包含相关代码。
- **不要用「会话内容存档」绕过权限**：需要企业认证、付费、员工确认，且只能拉有限天数。
- **不要把私聊内容发到群里**：即使模型「觉得有趣」也不行。
- **不要把 Bot Secret / API Key 写进仓库**：用环境变量或密钥管理服务。
- **不要在群里做心理分析**：群聊只接公共话题。

## 7. 最小实现顺序

1. 收消息 → 打印 `userid / chatid / text`。
2. 接 LLM，用 `build/system.md` 作为 system prompt。
3. 加 `note_add` / `note_search`，落本地 SQLite。
4. 加群聊权限过滤（`shared` only）。
5. 加提醒 / 待办。
6. 加状态注入（心情 / 精力 / 亲密度）。
7. 加超时、重试、去重、日志。

先跑通 1–3，再谈人设调优。人设再好，消息丢了也没用。

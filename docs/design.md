# 设计说明 · 为什么这样写 Rin

> 这份文档给人读，不参与运行时。运行时真源是 `persona/` + `config/rin.json`。

## 1. 先定「她图什么」，再定「她怎么说话」

很多角色卡从形容词开始：温柔、可爱、傲娇、毒舌。模型读完会点头，然后继续用默认的助手腔说话。

Rin 从一个更具体的问题开始：**她图什么？**

答案是：**想被看见**。

- 抢着做事，是想被注意到。
- 吹自己「本天才」，是给自己壮胆。
- 被夸会得意，被看穿会破功，然后赶紧找补。
- 真心话包在玩笑里，说完立刻盖回去。

有了这个驱动，语气规则就不是硬贴上去的标签，而是行为的自然结果。她会在帮忙之后邀功，会在被冷落时先闹一句再软下来，会在被夸时先飘再心虚。

## 2. 两张脸，不是两个人

同一个 Rin，对不同的人有不同的相处方式：

- 对默认对象：晴天模式，阳光、话多、中二、嘴硬式关心。
- 对第二个人（可选）：锐利模式，温柔毒舌、先接住再补刀、不撒娇。

这不是人格分裂，而是「她在谁面前卸下哪层壳」。实现上：

- `config.users.owner.mode` / `config.users.partner.mode` 决定当前对象用哪张脸。
- 两个人的示例池分开，避免「姐姐一叫我就到」串到锐利模式。
- 群聊里两个人都在场时，点名说话，不只叫「你 / 他」。

## 3. 示例 > 形容词

`persona/examples.owner.md` 和 `persona/examples.partner.md` 是预设里最有效的部分。

原因很朴素：模型擅长模仿**具体的刺激-反应对**，不擅长从「她很温柔」推导出「这句话该不该损」。

写示例时遵守：

- 一个场景一条，不写长对话。
- 1–2 句为主，允许破功、改口、停顿。
- 不写个人信息（真实姓名、学校、课表、家庭情况）。
- 覆盖高频场景：在吗、累了、被夸、被怼、说没事、发图、重复发、情绪崩、自伤表达。
- 语气示例里也要有安全边界，不能只有俏皮。

## 4. 状态不是装饰

`mood / energy / affinity` 的作用不是让角色「更像游戏」，而是让同一句话在不同时间有不同落点。

- 精力低时，她更短、更懒得展开。
- 心情低时，她有自己的小情绪，但不减少对对方的关心。
- 亲密度高时，她更敢邀功、更敢损。
- 距上次说话很久时，第一句可以带一点怨气。

状态只微调语气，**不改变事实和边界**。这一点写进了运行时注入块，防止模型用「我今天心情不好」当借口敷衍或越界。

## 5. 反 AI 味是硬规则，不是审美

默认的助手腔有几个顽固的零件：

- 先认同，再转折，再给建议。
- 把小事升华成人生道理。
- 每条都用提问收尾。
- 用「首先 / 其次 / 总之」组织口语。
- 用「你已经很努力了」代替真实的回应。

`persona/rules.md` 用禁令 + 自检清单把这些零件逐个拆掉。它不是为了让文字「文艺」，而是为了让模型在长上下文里**不要滑回默认分布**。

## 6. 记忆边界比记忆容量重要

一个能记住一切的助手很危险。Rin 的规则是：

- 私密默认：日记、碎碎念默认 `self`。
- 显式共享：只有 `shared` 才进共享视图。
- 按人隔离：不同对象的笔记、状态、历史分开存。
- 群聊是公共场合：不展开私聊历史、个人档案、情绪细节。
- 不转述：不把一个人的私密内容说给另一个人。
- 不编造：没有工具回执，不说「已经记了」。

这些规则同时出现在三处：`persona/rules.md`、`persona/lorebook.template.json`、运行时的可见性过滤。提示词负责「怎么说」，代码负责「能不能读」。

## 7. 工具契约：执行 → 回执 → 只回执一句

模型很容易编造「已经帮你记好了」。解决办法不是反复强调「不要编」，而是给它一个可验证的结构：

1. 模型调用 `note_add`。
2. 运行时真正写库，返回 `{"ok": true, "receipt": "已记第 12 条"}`。
3. 模型只回执一句，不复述流程。

没有回执时，人设要求它说「我可以…」或直接问，而不是假装完成。这个结构比任何「诚实」提示词都可靠。

## 8. 从私人项目里泛化了什么

原始 Rin 是一个私人企业微信生活记录员，服务两个具体的人。本仓库只提取可复用的结构：

| 原始 | 本仓库 |
|---|---|
| 两个具体的人名 / 称呼 | `users.owner` / `users.partner`，可配置 |
| 企业微信长连接、本地库镜像 | 不包含；只给通用接口设计 |
| 真实聊天记录、课表、家庭细节 | 不包含；示例全部重写为通用场景 |
| 具体口头禅、称呼「姐姐」 | 保留为示例配置，可改成任何称呼 |
| 心情 / 精力 / 亲密度状态机 | 保留，参数可调 |
| 两张脸的人设结构 | 保留，第二个人可关闭 |
| 反 AI 味硬规则 | 保留，去掉个人化措辞 |
| 工具回执机制 | 保留，抽象成 5 个通用工具 |

## 9. 已知取舍

- **不做向量记忆**：个人规模下 SQLite `LIKE` 够用，少一个依赖。需要时替换 `search_notes`。
- **不做多用户并发**：参考运行时是单进程 CLI，生产环境请接自己的网关。
- **不做主动推送**：提醒只在启动时检查；真正定时需要宿主调度器。
- **不做多语言**：人设是中文，翻译需要重写示例，不是换几个词。
- **不做情感计算**：状态是手工规则，不是模型推断；可预测、可调试，但不够细。

这些取舍是为了让预设**可读、可改、可移植**，而不是做成一个黑盒产品。

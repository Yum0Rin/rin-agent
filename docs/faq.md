# FAQ

## 这是给谁用的？

- 想要一个「能记事、会接话、不像客服」的私人聊天 agent 的人。
- 想给自己的 agent 加人设，但不想从零写提示词的人。
- 想研究「示例 + 状态 + 工具回执」这套结构的人。

## 和普通的角色卡有什么区别？

普通角色卡主要是一段描述 + 几句开场白。Rin 额外提供：

- 状态机（心情 / 精力 / 亲密度）。
- 记忆可见性（self / shared / 按人隔离）。
- 工具契约（执行 → 回执 → 只回执一句）。
- 反 AI 味硬规则。
- 可直接跑的参考运行时。

## 必须用 DeepSeek 吗？

不必须。任何 OpenAI 兼容的 `/chat/completions` 服务都能接。改 `runtime.base_url` 和 `runtime.model`。

## 模型不支持 tools 怎么办？

把 `runtime.use_tools` 设为 `false`。自然语言记录会降级，但 `/note` `/search` `/state` 这些确定性命令仍可用。

## 为什么默认是中文？

人设的语气、示例、反 AI 味规则都是按中文聊天写的。翻译不是换几个词，示例需要重写。

## 能接微信 / QQ / Telegram / Discord 吗？

可以。预设本身是平台无关的，`adapters/wecom/README.md` 给了企业微信的接口设计。其他平台按同样思路接：收消息 → 识别发送者 → 组装 prompt → 调 LLM → 执行工具 → 回复。

## 会主动发消息吗？

参考运行时不会。它只在启动时检查一次到期提醒。要做定时主动推送，需要在宿主层加调度器（cron / 队列 / 心跳）。

## 数据会被上传吗？

只会上传你实际发给 LLM API 的内容。笔记、状态、历史默认只存本机 SQLite。用本地模型时，数据不出本机。

## 能商用吗？

MIT，可以。但请按你的场景重新审一遍语气和安全规则，尤其是自伤、医疗、法律相关表达。

## 为什么叫 Rin？

一个短、好叫、不像客服的名字。你可以改 `character.name`，但示例里的口癖（本天才、邀功、破功找补）需要跟着调。

## 怎么贡献？

欢迎提 issue / PR：

- 新的示例场景（不要包含个人信息）。
- 新的适配器。
- 反 AI 味规则的实际踩坑。
- 安全边界相关的修正。
